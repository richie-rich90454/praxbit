# API endpoints

All routes below are under `/api/v1` unless marked otherwise. Cookie-authenticated mutations require `x-csrf-token`. Bearer-authenticated requests use `authorization: Bearer <token>`. “Auth” means a valid session is required; “optional auth” means the route returns public data when signed out and personal data when signed in.

## Capabilities

### `GET /capabilities`

Public. Reports runtime features that the client must not assume:

```json
{ "aiTutor": false }
```

`aiTutor` is true only when a complete AI provider configuration is present. It never exposes the provider URL, key, or model. The web client hides the live tutor and keeps curated hints when it is false.

## Auth

### `GET /auth/csrf`

Public. Sets the readable `praxbit_csrf` cookie and returns:

```json
{ "csrfToken": "…" }
```

Call this before registration, login, or any cookie-authenticated mutation.

### `POST /auth/register`

Public, CSRF required. Body `RegisterRequest`:

```json
{
    "handle": "ada_learner",
    "displayName": "Ada",
    "password": "at-least-ten-characters"
}
```

- `handle`: 3–24 lowercase letters, numbers, or underscores.
- `displayName`: optional, 1–40 characters; defaults to the handle.
- `password`: 10–200 characters.
- Promotes the account to admin if the handle is in `ADMIN_HANDLES`.
- Creates the account, preferences, and campus world in one transaction.
- Sets the session cookie.
- Returns `201` with `{ user, preferences }`, plus `nativeToken` when `x-praxbit-client: native`.
- `409 handle_taken` if the handle already exists.

### `POST /auth/login`

Public, CSRF required. Body `LoginRequest` `{ handle, password }`. Sets the session cookie and returns `{ user, preferences }`, plus `nativeToken` for native clients. `401 unauthorized` for an unknown handle or wrong password; the message does not reveal which.

### `POST /auth/logout`

Auth optional, CSRF required. Revokes the current session if one exists, clears the cookie, and returns `204`.

### `DELETE /auth/sessions`

Auth required. Revokes every session for the account, clears the cookie, and returns `204`. The current request is included in the revocation.

## Me and account

### `GET /me`

Auth required. Returns `MeResponse`:

```json
{
    "user": { "id": "…", "handle": "…", "displayName": "…", "role": "member", "createdAt": "…" },
    "preferences": {
        "interests": ["everything"],
        "textScale": 1,
        "motion": "system",
        "sound": false,
        "challenge": "standard",
        "reminders": { "enabled": false, "quietStart": "22:00", "quietEnd": "08:00" },
        "aiTutor": false
    },
    "progress": {
        "experience": 0,
        "level": 1,
        "streakDays": 0,
        "longestStreak": 0,
        "placementSkippedSkills": [],
        "achievements": []
    },
    "completions": []
}
```

### `GET /me/progress`

Auth required. Returns `{ progress, mastery, reviews }`. Mastery and reviews are arrays of `SkillMastery` and `ReviewItem`.

### `POST /me/export`

Auth required, CSRF required. Body must be an empty object `{}`. Returns an `ExportBundle` with the account, preferences, progress, mastery, reviews, evidence, completions, worlds, and achievements. This is a JSON response, not a downloadable file generated by the server.

### `DELETE /me`

Auth required, CSRF required. Hard-deletes the user and cascading personal rows, clears the cookie, and returns `204`. An audit entry is retained without actor or target identifiers. Local device data is not deleted.

### `POST /me/evidence`

Auth required, CSRF required. Body `{ evidence: EvidenceSubmission }`. Applies evidence, recomputes affected mastery, advances review schedules for review-category evidence, and evaluates achievements. Returns `EvidenceResult`:

```json
{
    "accepted": true,
    "mastery": [ … ],
    "reviews": [ … ],
    "progress": { … },
    "achievements": [ … ]
}
```

The mission must exist and the mission version must match. Use `POST /attempts/{id}/evidence` when the evidence belongs to a started attempt.

## Attempts and evidence

### `POST /attempts`

Auth required, CSRF required. Body `{ missionId, missionVersion }`. Returns `201 { attemptId, startedAt }`. The mission must exist, the version must match, and an attempt row is inserted with the start time.

### `POST /attempts/{id}/evidence`

Auth required, CSRF required. Body `{ evidence }`. The attempt must belong to the user. If evidence has an `attemptId`, it must match the path. Otherwise the server fills it in. Returns `EvidenceResult`.

## Sync

### `POST /sync`

Auth required, CSRF required. Body `{ operations: SyncOperation[] }`, maximum 50 operations. Returns a `SyncResponse` with per-operation results and the full snapshot:

```json
{
    "results": [
        { "operationId": "…", "kind": "world-action", "status": "accepted", "worldVersion": 5 },
        { "operationId": "…", "kind": "mission-completion", "status": "duplicate", "code": "already_completed" }
    ],
    "mastery": [],
    "reviews": [],
    "progress": { … },
    "achievements": [],
    "completions": [],
    "world": { … },
    "preferences": { … }
}
```

Operation kinds and idempotency are documented in [sync.md](../architecture/sync.md). A conflict (`world_version_conflict`, `project_revision_conflict`) or rejection is returned inside `results`; the HTTP request still returns `200` when the sync itself completed.

## World

### `GET /worlds/{id}`

Auth required. `id` must be `campus`. Returns `{ world }`. A new account receives the initial deterministic world.

### `POST /worlds/campus/actions`

Auth required, CSRF required. Body `WorldActionRequest`:

```json
{
    "action": { "id": "restart-service", "systemId": "api" },
    "expectedVersion": 4
}
```

Returns `{ world }` on success. A stale version returns `409 world_version_conflict` with `details.currentVersion`. Action ids are listed in [world.md](../architecture/world.md#actions). The server validates the action schema and version; it does not currently verify that the learner completed a teaching mission for that action.

## Projects

### `GET /projects`

Optional auth. Returns an array of `ProjectDetail` summaries. Signed-out callers get `currentRevision: 0` and no revisions. Signed-in callers get their current revision and timestamp, with an empty revisions array.

### `GET /projects/{id}`

Optional auth. Returns one `ProjectDetail` with the project summary and, when signed in, the revision history. `404 project_not_found` for an unknown id.

### `POST /projects/{id}/revisions`

Auth required, CSRF required. Body `ProjectRevisionRequest`:

```json
{
    "baseRevision": 2,
    "message": "Add the status table",
    "files": { "index.html": "<!doctype html>…" }
}
```

- At most 80 files and 900,000 total UTF-8 bytes.
- Paths must be relative, at most 200 characters, and free of `..`, backslashes, absolute prefixes, control characters, and null bytes.
- `baseRevision` must match the current revision; otherwise `409 project_revision_conflict` with `details.currentRevision`.
- Returns the updated `ProjectDetail` with the new revision.

## Clubs and events

### `GET /clubs`

Auth required. Returns the authenticated account's clubs as an array of `Club`.

### `POST /clubs`

Auth required, CSRF required. Body `{ name }` with 2–60 characters. Creates a club, makes the caller the owner, allocates an invite code, and returns `201 Club`.

### `POST /clubs/join`

Auth required, CSRF required. Body `{ inviteCode }` with 6–24 characters. Returns the joined `Club`. `404 club_not_found` if no club matches the code.

### `GET /clubs/{id}`

Auth required. Returns `ClubDetail` for a member or an admin. Non-members get `403 club_forbidden`. The detail includes members, public events (without answer hashes or salts), leaderboard, and the caller's verified submissions.

### `POST /clubs/{id}/join`

Auth required, CSRF required. Body `{ inviteCode }`. The code must belong to this club. Returns the joined `Club`.

### `POST /clubs/{id}/reports`

Auth required, CSRF required. Body `{ reason }` with 5–500 characters. Returns `201 { reportId }`. Reports are visible to admins. This is a reporting foundation, not a complete moderation workflow.

### `GET /events`

Public. Returns the weekly club events as an array. Answer hashes and salts are not exposed.

### `POST /events/{id}/submissions`

Auth required, CSRF required. Body `{ eventId, answer }`; `eventId` must match the path. The caller must belong to at least one club. The answer is compared against a salted SHA-256 hash in constant time. Returns `EventSubmissionResponse`:

```json
{
    "verified": true,
    "points": 100,
    "leaderboard": [{ "handle": "…", "displayName": "…", "points": 100, "verifiedAt": "…" }]
}
```

A wrong answer returns `verified: false`, `points: 0`, and the leaderboard. It does not reveal the correct answer. A verified submission is not overwritten; an unverified attempt can be retried.

## AI

### `POST /ai/hints`

Auth required, CSRF required. Body `AiHintRequest`:

```json
{
    "missionId": "campus.page-with-no-identity",
    "stepId": "structure",
    "question": "Why is a caption useful?",
    "code": "<optional learner code, max 4000 chars>"
}
```

- Requires a configured provider (`AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`) and `aiTutor: true` in preferences.
- Per-user limit: 10 hints/hour by default.
- Returns `{ text, model, remaining }` with a privacy notice appended to the text.
- `503 ai_unavailable` when the provider is not configured.
- `403 ai_disabled` when the learner has not enabled AI tutoring.
- `429 ai_quota_exceeded` when the hourly quota is exhausted.
- `502` / `504` for provider failure or timeout.

The AI is not the grader. It returns explanatory text only.

## Catalog

### `GET /catalog`

Public. Returns the validated content catalog:

```json
{
    "version": 1,
    "skills": [ … ],
    "tracks": [ … ],
    "missions": [ { "id": "…", "title": "…", "runtime": { "kind": "…", "label": "…", "capabilities": [ … ] }, … } ],
    "projects": [ … ],
    "placement": { … },
    "achievements": [ … ],
    "runtimes": [ … ]
}
```

Mission summaries omit the full steps and lesson body. Use `/missions/{id}` for the complete definition.

### `GET /skills/{id}`

Public. Returns one `Skill` definition. `404 skill_not_found` for an unknown id.

### `GET /missions/{id}`

Public. Returns `{ mission, runtimeLabel }`. The mission is the full validated manifest, including steps, hints, misconceptions, and accessibility notes. `404 mission_not_found` for an unknown id.

## Admin

All admin routes require `role: "admin"`. `403 admin_required` otherwise.

### `GET /admin/overview`

Returns aggregate counts: users, active sessions, evidence, completions, clubs, verified event submissions, open reports, and `generatedAt`. No personal content.

### `GET /admin/audit`

Cursor pagination: `?limit=1..50&cursor=…`. Returns `{ items, nextCursor, limit }`. Items contain actor id, action, target type/id, request id, metadata, and timestamp. Metadata is JSON and must not contain secrets.

### `GET /admin/reports`

Returns `{ items }` with up to 100 open club reports.

### `POST /admin/reports/{id}/resolve`

CSRF required. Marks an open report as reviewed. Returns `204`. `404 report_not_found` if it is not open or does not exist.

## Operations

These routes are not under `/api/v1`:

| Route                      | Auth | Response                                                   |
| -------------------------- | ---- | ---------------------------------------------------------- |
| `GET /healthz`             | none | `200 { status: "ok", uptimeSeconds }`                      |
| `GET /readyz`              | none | `200 { status: "ready" }` or `503 { status: "not_ready" }` |
| `GET /api/v1/openapi.json` | none | OpenAPI 3.1 document                                       |

The health routes are for operators and the proxy. Do not use them as decorative user-facing status messages.
